전체 흐름: 모든 동작은 하나의 모양입니다

B1-1 포트폴리오 — 외부 라이브러리 없이 HTML·CSS·JavaScript만으로 만든 반응형 자기소개 페이지입니다. (sarguments.github.io/b1-1-portfolio)

  • 사용자 행동을 addEventListener로 받고, 값을 setState로 바꾸고, 적용 함수가 화면을 다시 그립니다. 이 페이지의 모든 동작이 이 순서입니다.
  • 값을 바꾸는 통로가 setState 하나라서, "지금 화면이 왜 이렇게 보이는가"를 거슬러 올라가면 항상 STATE에 닿습니다.
// 화면을 결정하는 값은 한 객체에 모읍니다
const STATE = {
  theme: root.getAttribute('data-theme') || 'light',   // 지금 테마
  menuOpen: false,                                     // 메뉴 열림/닫힘
  repos: [],                                           // API에서 받은 저장소 목록
  reposFilter: '전체',                                  // 언어 필터 기준
};

// 값은 setState로만 바꾼다 — 직접 대입은 금지
function setState(patch) {
  Object.assign(STATE, patch);   // patch에 온 키만 STATE에 복사
  // 디버그 스위치를 켠 경우에만 "방금 뭐가 바뀌었나"가 찍힌다
  if (window.__B11_DEBUG) console.debug('[B1-1 STATE]', patch);
}

한 번의 클릭을 따라가 보면 — 테마 버튼을 누르면 setState({ theme: 'dark' })가 호출됩니다. Object.assign은 patch로 온 키만 복사해서 붙이므로 theme만 바뀌고 나머지 셋(menuOpen·repos·reposFilter)은 그대로입니다. 그 다음 applyTheme()이 바뀐 값을 읽어 화면을 다시 그립니다. STATE.theme = 'dark'처럼 직접 대입하지 않고 일부러 함수를 거치는 이유는 세 번째 줄에 있습니다. 통로가 하나니 이 한 곳에서 이 페이지의 모든 값 변경을 지켜볼 수 있습니다.

이 뒤의 열다섯 장이 각각 "어디서 받고, 어떤 값을 바꿔, 무엇을 다시 그리는지"를 보여줍니다.

🔤 addEventListener — “이 요소에서 저 일이 일어나면 이 함수 실행”을 등록 · DOM — HTML 구조를 브라우저가 나무 모양 객체로 만들어 놓은 것 · 적용 함수 — STATE의 값을 읽어 화면을 다시 그리는 함수 · patch — setState에게 “바뀐 것만” 넘기는 객체 · Object.assign — 한 객체의 속성을 다른 객체에 복사하는 함수

Q2. 테마 토글이 새로고침 후에도 유지되는가

  • 버튼을 누르면 theme 값이 반전하고, applyTheme이 <html>의 data-theme 속성을 바꾸면서 localStorage에 저장합니다. 저장은 try/catch로 감싸서, 저장소가 막혀도 화면 전환 자체는 동작합니다.
  • 새로고침 후 복원의 주체는 main.js가 아니라 <head>의 인라인 스크립트입니다. 첫 그림이 그려지기 전에 저장된 값을 읽어 속성을 먼저 박기 때문에, 흰 화면이 번쩍이는 FOUC가 없습니다. main.js는 defer라 이보다 늦게 실행됩니다.
  • 저장된 값이 없으면 OS 설정(prefers-color-scheme)을 따릅니다.
<head> 안에서 먼저 실행 — 그리기 전에 테마를 박는다
<script>
  (function () {
    try {
      const saved = localStorage.getItem('user-theme');
      const systemDark =
        window.matchMedia('(prefers-color-scheme: dark)').matches;
      document.documentElement.setAttribute(
        'data-theme', saved || (systemDark ? 'dark' : 'light'));
    } catch (e) {}
  })();
</script>
버튼을 누르면 — main.js
themeButton.addEventListener('click', () => {
  setState({ theme: STATE.theme === 'dark' ? 'light' : 'dark' });

function applyTheme() {
  root.setAttribute('data-theme', STATE.theme);          // 화면 전환
  try {
    localStorage.setItem('user-theme', STATE.theme);     // 복원용 저장
  } catch { /* 막혀도 메모리 상태만 유지, 화면은 동작 */ }
  themeButton.textContent = STATE.theme === 'dark' ? '라이트 모드' : '다크 모드';
}
🔤 localStorage — 새로고침에도 남는 브라우저 안쪽 저장 공간 · FOUC — 스타일 붙기 전 흰 화면이 찰나 번쩍이는 현상 · defer — 스크립트를 미리 받되 HTML 해석이 끝난 뒤 실행 보장 · prefers-color-scheme — OS가 다크 모드인지 물어보는 시스템 설정

Q3. 메뉴·등장 애니메이션·맨 위로 버튼

  • 메뉴: 햄버거 버튼은 setState({menuOpen}) → applyMenu. 메뉴 표시와 aria-expanded를 같은 함수에서 함께 바꿔서, 눈으로 보이는 열림과 스크린리더가 알려주는 열림이 어긋나지 않습니다.
  • 등장: 스크롤 이벤트로 매번 계산하면 레이아웃을 다시 짜는 작업(Reflow)이 반복돼 버벅입니다. 그래서 브라우저에 감시를 맡깁니다. IntersectionObserver가 구역의 20%(threshold: 0.2)가 보일 때 클래스를 붙이고, unobserve로 그 구역 감시를 끕니다. 등장은 한 번뿐입니다.
  • 맨 위로: 스크롤 이벤트 하나에서 300px를 넘으면 버튼을, 60px를 넘으면 내비 배경을 표시로 바꿉니다. 클릭하면 scrollTo({behavior:'smooth'})로 미끄러지듯 올라갑니다.
function applyMenu() {
  nav.classList.toggle('active', STATE.menuOpen);   // 보이는 메뉴
  // 스크린리더에도 같은 상태를 함께 넘긴다
  menuButton.setAttribute('aria-expanded', String(STATE.menuOpen));
}

const watcher = new IntersectionObserver((entries) => {
  entries.forEach((entry) => {
    if (entry.isIntersecting) {
      entry.target.classList.add('visible');   // 등장
      watcher.unobserve(entry.target);         // 본 구역은 감시 종료
    }
  });
}, { threshold: 0.2 });

window.addEventListener('scroll', () => {
  topButton.classList.toggle('show', window.scrollY > 300);
  nav.classList.toggle('scrolled', window.scrollY > 60);
});
🔤 IntersectionObserver — “요소가 화면에 들어왔나”를 브라우저가 대신 감시하는 API · threshold 0.2 — 20% 보일 때 발동 · unobserve로 본 구역은 감시 종료 · aria-expanded — 버튼이 여는 것이 지금 열렸는지 스크린리더에 알림 · Reflow — 레이아웃을 다시 짜는 계산 — 스크롤마다 하면 버벅임

Q4. 저장소 목록과 로딩·에러·빈 상태

  • fetch의 함정부터: 서버가 404나 403으로 답해도 fetch 자체는 성공으로 끝납니다. 거절되는 건 망이 끊길 때뿐입니다. 그래서 res.ok를 직접 검사해서 실패를 내가 만듭니다.
  • 화면 상태는 넷입니다. 로딩 문구 → 성공(문구를 비우고 카드 렌더) · 목록이 비면 빈 결과 문구 · 오류(403 한도 / 404 사용자 없음 / 그 외 HTTP / 망 단절·타임아웃).
  • 타임아웃은 8초(AbortController), 재시도는 버튼으로만 수동, 캐싱은 없습니다.
async function loadRepos() {
  // ① 로딩
  reposStatus.textContent = '저장소 목록을 불러오는 중입니다.';
  const controller = new AbortController();
  // 8초 후 요청 취소
  const timeoutId = setTimeout(() => controller.abort(), 8000);
  try {
    const res = await fetch(reposURL, { signal: controller.signal });
    // ② 실패를 내가 만든다 — fetch는 404·403도 성공이라 ok를 직접 검사
    if (!res.ok) {
      if (res.status === 403)
        throw new Error('API 호출 한도를 초과했습니다. 잠시 후 다시 시도해주세요.');
      if (res.status === 404) throw new Error('사용자를 찾을 수 없습니다.');
      throw new Error(`로드 실패 (HTTP ${res.status})`);
    }
    // ③ 성공 → 카드 렌더
    renderRepos(await res.json());
    renderFilters(STATE.repos);
  } catch (err) {
    // ④ 오류 문구 + 수동 재시도 버튼 표시
    reposStatus.textContent = timedOut
      ? '요청 시간이 초과됐습니다. 다시 시도해주세요.'
      : err.message;
    reposRetry.hidden = false;
  } finally {
    // ⑤ 성공·실패 모두 타이머 정리
    window.clearTimeout(timeoutId);
  }
}
🔤 fetch · 프로미스 — 서버에 데이터를 주문하는 함수 · “나중에 답장” 표 · response.ok — 서버가 200번대로 성공 답했는지 표시 · AbortController — 이미 보낸 요청을 취소하는 손잡이

Q5. 폼 오류에 즉각 피드백이 뜨는가

  • 브라우저 기본 검증은 폼에 novalidate를 붙여 껐습니다. 네이티브 풍선이 먼저 뜨면 커스텀 문구가 가려지기 때문입니다.
  • 오류는 입력칸에 aria-describedby로 연결된 role=alert 자리에 뜹니다. 눈으로 보이는 문구와 스크린리더가 읽는 문구가 같은 자리 하나입니다.
  • 처음 제출이 실패한 뒤부터는, 타이핑하는 동안 그 필드만 즉시 재검사해서 오류 문구를 갱신합니다.

  <input type="text" id="contact-name" name="name" required

  ...
</form>

Q6. 왜 세 개의 파일인가

  • index.html은 구조, css/style.css는 표현, js/main.js는 동작. 역할을 나눠서 한 파일을 고쳐도 나머지가 무너지지 않습니다.
  • 연결은 HTML의 두 줄뿐입니다. defer는 HTML 해석을 막지 않으면서 해석이 끝난 뒤 순서대로 실행하라는 뜻입니다. async는 다운로드가 끝나면 중간에라도 실행되므로 DOM이 아직 없을 수 있습니다. 원문 요구사항이 defer를 지정한 이유입니다.
  • 같이 지킨 규칙: var 금지(함수 스코프·호이스팅·중복 선언 문제 때문에 상수 const, 재할당만 let), 인라인 onclick 금지, 인라인 스타일 금지. JS는 최상위에서 'use strict'와 DOMContentLoaded로 준비를 보장합니다.
<head> 안에서 — 연결의 전부
<link rel="stylesheet" href="css/style.css" />
<script src="js/main.js" defer></script>
🔤 defer · async — 해석 끝난 뒤 실행 · 다운로드 끝나면 중간에도 실행(DOM 준비 안 됨) · DOMContentLoaded — HTML 해석이 끝나 준비됐다는 이벤트 · const · let — 재할당 불가 상수 · 재할당 가능 선언(var의 스코프·호이스팅 문제 회피)

Q8. CSS 변수를 왜 모았나

  • 색·간격·모서리 값을 :root에 한 번씩 정의하고 var(--이름)으로 재사용합니다. 값을 고칠 일이 생기면 정의 한 곳만 건드립니다.
  • 다크모드는 새 스타일이 아니라 같은 이름의 다른 값입니다. [data-theme="dark"] 블록이 변수만 덮어쓰면, 변수를 참조하는 아래쪽 스타일 전부가 자동으로 따라 바뀝니다.
  • JS는 색 값을 전혀 만지지 않습니다. data-theme 속성만 바꿉니다. 표현은 CSS의 일이라는 분리가 테마 전환에서도 지켜집니다.
:root {                          /* 라이트가 기본값 */
  --bg: #ffffff;
  --text: #1a1b1e;
  --accent: #1f6feb;
}
[data-theme="dark"] {            /* 이름은 두고 값만 갈아끼움 */
  --bg: #121212;
  --text: #f1f3f5;
  --accent: #6ea8fe;
}

body { background: var(--bg); color: var(--text); }   // 참조자는 그대로
🔤 CSS 사용자 정의 속성 — 값에 --이름을 붙여 한 곳에 정의하고 재사용 · :root — 문서의 최상위 — 변수를 모으는 정의 자리 · data-* 속성 — HTML·CSS·JS가 자유 이름으로 약속을 주고받는 속성

Q9. onclick 대신 addEventListener

  • 구조와 동작을 분리합니다. HTML에 행동을 박아두면 세 파일로 나눈 의미가 무너집니다.
  • onclick은 속성 하나라서 두 번째 대입이 첫 번째를 덮어씁니다. addEventListener는 같은 요소에 여러 리스너를 붙일 수 있습니다. 이 코드에 리스너는 열 곳이고, HTML에는 onclick이 한 건도 없습니다.
  • 필터 버튼은 이벤트 위임입니다. 버튼마다 리스너를 붙이면 목록을 다시 그릴 때마다 리스너도 다시 붙여야 합니다. 부모 리스너 하나면 다시 그려도 붙일 게 없습니다.
// 버튼은 식별 값만 싣습니다 — 리스너를 달지 않아요
function renderFilters(repos) {
  langs.forEach((lang) => {
    const btn = document.createElement('button');
    btn.textContent = lang;
    btn.dataset.filter = lang;         // data-filter 값만
    filters.appendChild(btn);
  });
}

// 클릭은 부모(#repos-filters) 리스너 하나가 받고,
// 눌린 버튼은 closest로 고릅니다
document.querySelector('#repos-filters')
  .addEventListener('click', (event) => {
    const btn = event.target.closest('button[data-filter]');
    if (!btn) return;
    setState({ reposFilter: btn.dataset.filter });
    renderRepos(STATE.repos);
  });
🔤 이벤트 위임 — 자식 여러 개의 이벤트를 부모 리스너 하나로 받음 · closest() — 눌린 지점에서 조건에 맞는 조상을 거슬러 검색 · onclick — HTML에 직접 박는 행동 — 재대입 시 덮어써짐

Q11. async/await·try/catch의 분기 따라가기

  • try 안의 순서: 로딩 상태 세팅 → fetch(url, {signal}) → res.ok 검사 → json() → 렌더. 단계마다 실패 지점이 다릅니다.
  • 실패 네 종류에 문구 네 개를 대응시켰습니다. 403 한도 초과 / 404 사용자 없음 / 그 외 HTTP 상태 코드 / 망 단절·타임아웃. "catch 하나로 다 처리"가 아니라, 화면에 보여줄 말이 다르기 때문에 던지는 자리도 나뉘어 있습니다.
  • 타임아웃은 8초에 controller.abort()를 걸어 요청을 취소하고, finally에서 타이머를 정리합니다. 성공해도, 실패해도 남는 게 없도록.
const controller = new AbortController();
let timedOut = false;
const timeoutId = setTimeout(() => {
  timedOut = true;
  controller.abort();
}, 8000);
try {
  const res = await fetch(reposURL, { signal: controller.signal });
  // 여기서 실패를 '던진다' — 종류마다 화면 문구가 달라야 해서
  if (!res.ok) {
    if (res.status === 403)
      throw new Error('API 호출 한도를 초과했습니다. 잠시 후 다시 시도해주세요.');
    if (res.status === 404) throw new Error('사용자를 찾을 수 없습니다.');
    throw new Error(`로드 실패 (HTTP ${res.status})`);
  }
  renderRepos(await res.json());
} catch (err) {
  // 던진 것과 망 단절(타임아웃 포함)이 여기로 모인다
  reposStatus.textContent = timedOut
    ? '요청 시간이 초과됐습니다. 다시 시도해주세요.'
    : err.message;
  reposRetry.hidden = false;
} finally {
  // 성공/실패 무관하게 타이머 정리
  window.clearTimeout(timeoutId);
}
🔤 async · await — 시간 걸리는 일을 윗줄→아랫줄 읽듯이 쓰는 문법 · try · catch · finally — 시도 → 오류 처리 → 무조건 마무리 · throw — catch로 넘길 오류를 직접 만들어 던짐

Q12. 데이터가 카드가 되는 세 단계

API에서 온 배열을 화면의 카드로 바꾸는 파이프라인입니다. 고르고(filter) → 카드 문장으로 바꾸고(map) → 하나씩 꽂습니다(forEach). 그리고 심기 전에 안전 문자로 갈아두는 단계가 한 겹 더 있습니다.

const shown = repos.filter((repo) =>
  STATE.reposFilter === '전체' || (repo.language || '기타') === STATE.reposFilter);

shown
  .map((repo) => {
    const { name, html_url: url, description } = repo;   // 구조분해 할당
    const desc = description || '설명 없음';
    // 템플릿 리터럴로 조립 — 외부 값은 전부 escapeHTML
    return `<article>
      <a href="${escapeHTML(url)}">${escapeHTML(name)}</a>
      <p>${escapeHTML(desc)}</p>
    </article>`;
  })
  .forEach((html) => reposList.insertAdjacentHTML('beforeend', html));

// 이름에 <script>를 심은 저장소가 내 페이지에서 실행될 수 있습니다.
// 그래서 심기 전에 안전 문자로 바꿉니다 (XSS 방지).
function escapeHTML(value) {
  return String(value)
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;').replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;').replace(/'/g, '&#39;');
}
🔤 구조분해 할당 — const { name } = repo; 객체에서 값 한 줄 추출 · 템플릿 리터럴 — `` ` `` 문자열에 ${ }로 값 박아 조립 · insertAdjacentHTML — HTML 문자열을 지정 위치에 끼워 넣기 · escapeHTML (XSS 방지) — < > " 등을 안전 문자로 바꿔 문자로만 취급

Q13. Flex와 Grid는 어디에, 왜

  • 기준은 축입니다. 방향이 하나면 Flex, 두 개면 Grid. 헤더 한 줄, 내비 한 줄, 필터 한 줄처럼 좌우 정렬만 필요하면 1차원인 Flex로 충분합니다.
  • 저장소 카드는 행과 열이 같이 굴러가야 하는 2차원이라 Grid입니다. 기본은 1열이고, 넓어지면 repeat(auto-fit, minmax(260px, 1fr))이 남는 폭을 쪼개 열을 스스로 늘립니다. 1200px 이상에서는 repeat(4, 1fr)로 열 수를 명시 고정합니다.
  • auto-fit를 쓴 이유: 카드가 적어도 빈 트랙을 접어서 채웁니다. auto-fill이었다면 빈칸을 그대로 남겨 카드가 한쪽으로 쏠립니다.
/* 한 축 → Flex */
header { display: flex; align-items: center; }
/* 링크 4개를 폭 전체에 균등 배치 */
nav    { justify-content: space-between; flex: 1; }
footer { display: flex; justify-content: space-between; }

/* 두 축 → Grid */
#repos-list { display: grid; grid-template-columns: 1fr; }  /* 기본 1열 */
@media (min-width: 768px) {
  #repos-list { grid-template-columns: repeat(auto-fit, minmax(260px, 1fr)); }
}
@media (min-width: 1200px) {
  #repos-list { grid-template-columns: repeat(4, 1fr); }
}
🔤 Flex — 한 줄(1차원) 정렬 도구 · Grid — 행과 열(2차원) 격자 도구 · space-between — 요소들을 폭 전체에 균등 배치 · auto-fill — auto-fit과 달리 격자 빈칸을 그대로 둠

Q14. STATE 객체가 왜 필요한가

  • 화면을 결정하는 값 네 개(theme, menuOpen, repos, reposFilter)를 한 객체에 모아뒀고, 바꾸는 통로는 setState 하나입니다. 그리는 함수들은 읽기만 합니다. "이 값은 어디서 바뀌나요"라는 질문에 한 곳으로 답할 수 있습니다.
  • 변수로 흩어두면 핸들러가 늘수록 화면의 원인을 역추적하기 어려워집니다. 변경 지점이 한 곳이라 디버그 로그도 setState 한 곳에 붙었습니다.
  • 정직한 예외 두 개: 폼의 유효성(valid)은 지역 변수에 바로 쓰고, 스크롤 표시(300/60px)는 화면을 '결정'하는 값이 아니라 지나가는 신호라서 클래스를 바로 토글합니다. 무엇을 모으고 무엇을 두지 않았는지 설명할 수 있어야 단일 진실 원천이 성립합니다.
🔤 STATE · setState — 화면 결정 값의 저장소 · 바꾸는 유일한 통로 · 단일 진실 원천 — 같은 값의 원본을 한 곳에 두는 설계 · 지역 변수 — 함수 안에서만 사는 1회용 값

Q15. 모바일 퍼스트로 쓴 이유

  • 기본 스타일이 곧 좁은 화면입니다. 내비는 숨김, 기술 목록 1열, 저장소 격자 1열이 기본값이고, 넓어지는 분기 min-width 세 개로 키워갑니다. style.css에 max-width 미디어쿼리는 하나도 없습니다.
  • 계산이 하나 사라집니다. 데스크톱을 기본으로 두면 좁아질 때마다 되돌림(max-width 분기)이 필요하지만, 기본이 좁으면 분기는 넓어지는 방향 한쪽뿐입니다.
  • 가치 기준의 선택이기도 합니다. 저사양·터치 환경이 먼저 보장됩니다. Q1이 '동작'을 물었다면, 이 장은 그 순서를 고른 '이유'를 답합니다.
/* 기본 = 모바일 */
nav         { display: none; }        /* 햄버거로 접음 */
#tech ul    { grid-template-columns: 1fr; }
#repos-list { grid-template-columns: 1fr; }

/* 넓어질 때만 덧입힘 — 되돌리는 분기 없음 */
@media (min-width: 768px)  { nav { display: flex; } ... }
@media (min-width: 1024px) { main { max-width: 1024px; } ... }
@media (min-width: 1200px) { main { max-width: 1200px; } ... }
🔤 min-width — 화면이 넓어질 때 도는 분기 조건 · max-width — 좁아질 때 되돌리는 분기 조건 — 이 페이지엔 없음 · 모바일 퍼스트 — 저사양·터치 환경이 먼저 보장되는 순서
